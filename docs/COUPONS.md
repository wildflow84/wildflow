# 쿠폰 판매

민아가 쿠폰 스크린샷을 올리면 번호를 읽어 저장하고, 대희 아빠의 **오늘 할 일**로 만들어 줘. 대희 아빠가 스크린샷을 저장해서 팔고, **할 일을 완료하면 판매 완료**야.
이미 판매한 번호를 또 올리면 "이미 판매한 쿠폰이야"라고 알려주고 **등록되지 않아**.

앱에서는 홈 위쪽 **기능(⊞) 메뉴 → 쿠폰 판매**로 들어가.

## 흐름

1. 쿠폰 판매 화면에서 **쿠폰 등록** → 갤러리에서 스크린샷 선택.
2. 앱이 스크린샷을 줄여서(약 900KB 이하 JPEG) 서버에 보내고, 서버가 구글 Cloud Vision 으로 글자를 읽어 쿠폰번호 후보를 돌려줘.
3. 읽은 번호를 확인/고치고(후보 중 고르거나 직접 입력) **등록**. 번호를 못 읽어도 직접 입력해서 등록할 수 있어.
4. 서버(`registerCoupon`)가 한 번에 만들어: 쿠폰 문서(판매 대기), 스크린샷, 대희 아빠 몫의 같이 보기 할 일 `쿠폰 판매 ····9012`(오늘, 종일). 대희 아빠에게 푸시도 가.
5. 대희 아빠는 그 할 일을 열어 **쿠폰 스크린샷 저장**(갤러리/다운로드)을 눌러 저장하고 판매해. 쿠폰 판매 화면의 쿠폰을 눌러도 저장할 수 있어.
6. 할 일을 **완료**하면 서버(`onItemWriteCoupon`)가 쿠폰을 **판매 완료**로 바꿔. 완료를 풀면 판매 대기로 돌아가. (앱, 위젯, 웹 어디서 완료해도 같아.)
7. 같은 번호를 다시 등록하려 하면: 판매 완료면 "이미 판매한 쿠폰이야", 판매 대기면 "이미 등록된 쿠폰이야"로 막혀. 번호가 곧 문서 id 라서 두 사람이 동시에 올려도 하나만 만들어져.
8. 아직 안 판 쿠폰의 할 일을 **지우면** 등록이 취소돼서 다시 올릴 수 있어. 이미 판 쿠폰의 할 일을 지워도 판매 기록은 남아.

판매하는 사람은 공간을 만든 사람(방장, `members` 맨 앞)이야.

## 설정 (한 번만)

번호 자동 읽기에 구글 **Cloud Vision API** 를 써. 안 켜져 있어도 앱은 동작하고, 번호를 직접 입력하게 돼.

1. [Cloud Vision API 사용 설정](https://console.cloud.google.com/apis/library/vision.googleapis.com?project=soondaehui) 페이지에서 **사용**을 눌러.
2. 요금: 월 1,000건까지 무료, 넘으면 1,000건당 약 1.5달러야. 쿠폰 한 장에 1건이라 사실상 무료야.

배포는 평소처럼 이 저장소의 CI 가 해 (보안 규칙, 함수 3개: `scanCoupon`, `registerCoupon`, `onItemWriteCoupon`).

## 저장과 보안

- 쿠폰 `spaces/{공간}/coupons/{번호}`, 스크린샷 `spaces/{공간}/couponImages/{번호}`(Firestore 문서에 이미지 바이트로 저장, 1MiB 한도 안).
- 보안 규칙: **공간 멤버만 읽기**, 쓰기는 모두 막고 서버 함수만 쓴다 (`tool/rules-test` 에 테스트).
- 할 일 항목에 `couponId` 가 붙고, 서버는 쿠폰의 `itemId` 와 같은 할 일일 때만 판매 완료로 바꿔서, 다른 항목이 같은 번호를 흉내 내도 소용없어.
- 번호 정규화: 대문자 영문/숫자 6~32자 (공백, 하이픈은 지워). 앱과 서버가 같은 규칙이야.

## 번호 읽는 방법 (`functions/coupon.js`)

"쿠폰번호", "교환번호", "PIN" 같은 말이 붙은 줄의 숫자 덩어리를 우선하고, 전화번호/대표번호/날짜/주문번호/금액처럼 보이는 건 뒤로 밀어서 최대 5개 후보를 점수순으로 줘. 영문+숫자 코드(`AB12-CD34-EF56`)도 읽어. 못 읽으면 직접 입력.

## 앞으로 기능 추가

달력이 아닌 기능은 **기능 메뉴**에 모아. 새 기능은 화면 파일을 만들고 `lib/features/feature_registry.dart` 의 `appFeatures` 에 한 줄 추가하면 메뉴에 나타나. (이름, 설명, 아이콘, 화면)
